# F01: API de donaciones y comedores populares

**Fecha:** 23 de noviembre de 2026

## Estado

**PARTIAL.** La API de donaciones está verificada y se importaron los registros públicos de comedores para Villa El Salvador. La fuente contiene un campo de dirección específica que no se guardó porque no permite distinguir con seguridad una dirección institucional de una ubicación personal. La columna `address` acepta nulos.

## Trabajo realizado

- Se reforzaron las validaciones de donaciones y reservas. Los identificadores mal formados responden 422 y los UUID válidos sin registro responden 404.
- La reserva se mantiene como una actualización condicional en PostgreSQL; dos intentos simultáneos no pueden reservar el mismo registro.
- Se agregó la tabla `community_kitchens` con un código de fuente único, ubicación, modalidad, estado publicado, conteo agregado, fuente y fechas.
- Se añadieron consultas paginadas a PostgreSQL para listar y consultar comedores.
- No se modificó `front/` ni se alteraron los nombres JSON de los endpoints existentes.

## Fuente e importación

Se consultó la capa [COMEDORES POPULARES de IDEP](https://www.idep.gob.pe/geoportal/rest/services/DATOS_ESPACIALES/ANTORCHA_INSTEG/MapServer/59) y su [endpoint de consulta](https://www.idep.gob.pe/geoportal/rest/services/DATOS_ESPACIALES/ANTORCHA_INSTEG/MapServer/59/query). La capa declara un máximo de 1.000 filas por respuesta y paginación. Se descargó en 12 páginas ordenadas por `OBJECTID_1`, con `resultOffset` y `resultRecordCount`, solicitando geometría en WGS84 (WKID 4326).

La descarga completa del servicio tuvo 11.822 registros. Al filtrar conjuntamente `ubigeo_dis='150142'` y `distrito='VILLA EL SALVADOR'`, se obtuvieron 242 registros. Se detectaron cero códigos de fuente duplicados y cero registros rechazados. Los nombres repetidos con códigos distintos se conservaron como registros diferentes.

Se guardó una copia saneada en `back/data/raw/comedores_idep_2026-11-23.json`. La lista permitida excluye `nombre_d_1` (nombre de responsable) y `direccion` (dirección específica); no se almacena información personal de responsables o beneficiarios. Las coordenadas se solicitaron en WGS84. El identificador `codigo_de` se utiliza para importaciones idempotentes; al repetir la importación se actualizaron 242 filas y no se insertaron duplicados.

Cinco nombres de la fuente:

- SAN MARTIN DE PORRAS
- LLANA VILLA
- AMAR ES VIDA
- SAN JUAN TADEO
- MARIA PARADO DE BELLIDO

La fuente publica el estado `ACTIVO` para los 242 registros importados. `verified_at` permanece nulo: el estado publicado no se presenta como una verificación de operación actual.

## Endpoints

Se verificaron los endpoints existentes de donaciones y se añadieron:

- `GET /api/community-kitchens?name=&district=&limit=&offset=`: búsqueda por nombre, filtro de distrito y paginación.
- `GET /api/community-kitchens/{id}`: detalle por identificador.

Ambos consultan PostgreSQL. La API no lee el archivo de descarga en cada solicitud.

## Pruebas y comprobaciones

- `docker compose exec -T back python -m pytest -q`: **8 passed**, 1 aviso de obsolescencia de `starlette.testclient` con `httpx`.
- HTTP: búsqueda filtrada devolvió 200; detalle devolvió 200; dos páginas de cinco elementos no se solaparon; OpenAPI incluyó ambas rutas.
- PostgreSQL: 242 comedores con 242 códigos únicos; los 242 tienen UBIGEO y distrito esperados; 242 tienen coordenadas; no se guardaron direcciones.
- Persistencia: tras reiniciar PostgreSQL permanecieron los 242 comedores y las tres donaciones de demostración.
